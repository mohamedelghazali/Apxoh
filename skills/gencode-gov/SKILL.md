# GENCODE-GOV — AI-Agent-Generated Software Governance Skill

**Official Definition:** *An Engineering Governance and Deterministic Verification Framework for Code, Applications, and Systems Generated by AI Coding Agents.*

**Core Mandate:** *Govern AI-Generated Code. Assure Engineering Integrity.*

## When to Activate and Consult This Skill

Consult and apply this skill automatically across **all software engineering tasks** whenever installed and available, including:

- Requirements analysis, specification refinement, and acceptance criteria design
- System and component architecture, API/schema design, and threat modeling
- Writing, scaffolding, refactoring, or migrating AI-generated or human-authored code
- Application security hardening, source security auditing, and dependency/supply-chain review
- Unit, integration, end-to-end, regression, and negative security test design and execution
- Code review, static analysis, performance/reliability engineering, and release readiness gating

## Mandatory 8-Stage Closed-Loop Workflow

Execute engineering tasks through this explicit closed loop, scaling depth to task scope without skipping verification:

```text
Inspect -> Plan -> Design -> Implement -> Verify -> Remediate -> Re-verify -> Report
```

1. **Inspect**: Read existing project layout, `.gencode-gov/project.yaml` (if present), language/tooling configs, trust boundaries, and active CI gates before editing code.
2. **Plan**: Identify applicable engineering domains (`requirements`, `architecture`, `code-quality`, `software-security`, `testing`, `performance`, `reliability`, `database`, `api-integration`, `devops`, `observability`, `privacy-compliance`, `scalability`, `infrastructure`, `maintenance`, `release`) and define concrete acceptance checks.
3. **Design**: Record non-trivial architectural choices, explicit interfaces, input validation boundaries, error semantics, and threat mitigations prior to implementation.
4. **Implement**: Write minimal, typed, modular, defensive code with explicit error handling, safe defaults, parameterized queries/commands, and zero hardcoded secrets or placeholder stubs.
5. **Verify**: Run independent deterministic verifiers (linters, static type checkers, unit/integration/negative-security test suites, security scanners, and `gencode-gov` CLI commands when installed).
6. **Remediate**: Fix every concrete defect, regression, lint/type error, or security finding at its root cause rather than suppressing warnings or weakening assertions.
7. **Re-verify**: Re-run the full affected verification suite against the final clean state so results reflect the exact code delivered.
8. **Report**: Summarize verified outcomes with concrete command outputs, test/coverage counts, artifacts, and explicit `BLOCKED` disclosures for any check that could not be executed.

## Non-Negotiable Fail-Closed Governance Controls

1. **Evidence Before Approval**: Never report `PASS`, readiness, test execution, coverage, or compliance without real, current execution evidence.
2. **Fail-Closed Honesty**: Missing tools, unavailable sandboxes, dirty working trees, unverified assumptions, or inaccessible external dependencies resolve strictly to `BLOCKED` or `needs_validation`—never `PASS`.
3. **Untrusted Producer Discipline**: Treat all AI-generated code, patches, and candidate vulnerability findings as unverified hypotheses requiring independent validation.
4. **Separation of Duties**: Never self-confirm security findings (`discoverer != verifier`), never bypass critical release gates, and delegate governed SAST/secret-scanning authority to TSAR when configured.
5. **Protected Governance Integrity**: Never delete failing tests, lower coverage thresholds, disable security checks, or alter protected governance/CI files without explicit maintainer authorization.

## Deterministic Evidence & CLI Execution

When the `gencode-gov` Python CLI is installed in the environment, execute the applicable commands and persist commit-bound evidence under `.gencode-gov/evidence/`:

```bash
gencode-gov inspect . --json
gencode-gov verify . --domain testing
gencode-gov verify . --domain code-quality
gencode-gov assess .
gencode-gov audit run . --profile standard --output-dir /tmp/gencode-gov-audit --record-evidence
gencode-gov report . --format markdown
```

Evidence records follow `schemas/evidence.schema.json`:

```json
{
  "evidence_id": "EVID-GENCODE-GOV-A1B2C3D4E5F6",
  "source": "gencode-gov",
  "source_version": "0.1.0",
  "commit_sha": "0123456789abcdef0123456789abcdef01234567",
  "executed_at": "2026-11-27T00:00:00Z",
  "status": "PASS",
  "artifacts": [{"path": ".gencode-gov/reports/pytest.xml", "sha256": "..."}]
}
```

When the `gencode-gov` CLI is not installed in the target project, enforce the identical GENCODE-GOV lifecycle and domain rules directly using the project's native test, typecheck, lint, build, and security toolchains, reporting exact commands run and marking unavailable checks as `BLOCKED`.
